# herdr-tab-name

herdr のタブ一覧を見ただけで「どのタブで何をしているか」が分かる状態を保つための skill。
ユーザーは複数タブで並行して Claude Code を動かしているので、タブ名が初期値のままだと
どれがどの作業か区別できなくなる。それを防ぐのが目的。

追加の LLM 呼び出しやファイル調査は不要。今の会話から分かる範囲でラベルを決め、
コマンドを1回実行するだけで終わる。所要時間はコマンド1回分に収めること。

## 手順

1. **環境変数 `HERDR_TAB_ID` を確認する。** 未設定なら herdr の外で動いているので、
   何もせずに終了して本来のタスクに戻る。

2. **ラベルを作る。** 日本語 8〜15 文字、体言止め。

   - 作業の「目的」を書く。ファイルパスやコマンド名、リポジトリ名ではない
   - 引用符・絵文字・句読点は含めない
   - 例: `認証バグ修正` / `CI高速化` / `検索APIの設計` / `デプロイ失敗の調査`
   - 悪い例: `main.go の修正`（ファイル名）、`作業`（短すぎて区別できない）、
     `ユーザー認証まわりのトークン検証処理のバグを直す`（長すぎてタブに収まらない）

3. **リネームを実行する。**

   ```
   herdr tab rename "$HERDR_TAB_ID" "<ラベル>"
   ```

   成功しても失敗しても、結果をユーザーに報告する必要はない。すぐ本来のタスクに移る。

## 更新するタイミング

- セッションで最初の作業指示を受けた直後（必須）
- 作業テーマが明確に変わったとき（例: 実装 → 別機能の調査、バグ修正 → リリース作業）

## 更新しないとき

- **同じ作業を継続している間**。毎ターン更新するとコマンド実行がノイズになり、
  タブ名も細かく揺れて逆に追いにくくなる。同じテーマの中での進捗や手順の切り替わりは
  「変わった」に含めない
- 挨拶や雑談だけで、まだ作業が始まっていないとき
- 単発の質問に答えるだけで、作業として継続しないとき

## 失敗したとき

リネームが失敗しても（herdr のソケットが応答しない、タブ ID が古いなど）、
エラーとして扱わず、ユーザーにも報告せず、黙って本来のタスクを続行する。
タブ名はあくまで補助情報であり、これが原因で本来のタスクを止める価値はない。
