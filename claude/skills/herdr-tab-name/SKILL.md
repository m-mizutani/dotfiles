# herdr-tab-name

herdr のタブ一覧を見ただけで「どのタブで何を、どの段階までやっているか」が分かる状態を
保つための skill。ユーザーは複数タブで並行して Claude Code を動かしているので、タブ名が
初期値のままだとどれがどの作業か区別できなくなる。それを防ぐのが目的。タブが分割されて
いる場合に備えて、pane 名も同じラベルにする。

追加の LLM 呼び出しやファイル調査は不要。今の会話から分かる範囲でラベルを決め、
コマンドを1回実行するだけで終わる。所要時間はコマンド1回分に収めること。

## 手順

1. **ラベルを作る。** `[<段階タグ>] <作業内容>` の形にする。作業内容は日本語 8〜15 文字、
   体言止め。

   - 作業の「目的」を書く。ファイルパスやコマンド名、リポジトリ名ではない
   - 引用符・絵文字・句読点は含めない（角括弧は段階タグのためだけに使う）
   - 例: `[impl] 認証バグ修正` / `[plan] 検索APIの設計` / `[refine] CI高速化`
   - 悪い例: `[impl] main.go の修正`（ファイル名）、`[impl] 作業`（短すぎて区別できない）、
     `[impl] ユーザー認証まわりのトークン検証処理のバグを直す`（長すぎてタブに収まらない）

2. **段階タグを選ぶ。** 今の会話から分かる範囲で、以下を主に使う。

   | タグ | 状態 |
   | --- | --- |
   | `plan` | 設計・仕様検討中。spec や実装方針を固めている段階 |
   | `impl` | 実装作業中。コードを書いている段階 |
   | `refine` | 一通り実装が終わったあと。レビューコメントの反映、指摘の修正 |

   この 3 つに限らない。上のどれにも当てはまらない作業なら、同じ粒度で英小文字の短い語を
   自分で選んでよい（例: 調査なら `research`、レビューなら `review`、運用作業なら `ops`、
   リリース作業なら `release`）。造語や独自の略語は使わず、素直な英単語 1 語にすること。
   段階が判断できないときはタグを付けずに作業内容だけにする。

3. **リネームを実行する。** 以下の形をそのまま1コマンドとして実行する。これ以外の
   コマンドは実行しないこと。

   ```
   herdr-label "<ラベル>"
   ```

   `herdr-label` は dotfiles の `bin/herdr-label`（`~/.local/bin/herdr-label` に
   シンボリックリンク）。タブ名と、pane の中にいれば pane 名の両方を設定する。
   環境変数の確認、herdr の外で動いているかの判定、失敗時の後始末はすべてスクリプト側で
   済むので、`$HERDR_TAB_ID` を自分で読んだり `if` / `&&` / `;` で条件分岐や
   コマンド連結をしたりしないこと（permission ルール `Bash(herdr-label:*)` に
   マッチしなくなり、許可プロンプトが出る）。

   成功しても失敗しても、結果をユーザーに報告する必要はない。すぐ本来のタスクに移る。

## 更新するタイミング

- セッションで最初の作業指示を受けた直後（必須）
- 作業テーマが明確に変わったとき（例: 実装 → 別機能の調査、バグ修正 → リリース作業）
- **段階タグが変わったとき**。作業内容が同じでもタグだけ差し替えて更新する。例:
  - 設計や spec が固まって実装に入った → `[plan]` から `[impl]`
  - 一通り実装を終えてレビューコメントの反映や指摘修正に入った → `[impl]` から `[refine]`
  - 指摘対応の途中で追加実装が必要になった → `[refine]` から `[impl]` に戻す

## 更新しないとき

- **同じ作業を同じ段階で継続している間**。毎ターン更新するとコマンド実行がノイズになり、
  タブ名も細かく揺れて逆に追いにくくなる。段階が変わらない範囲の進捗や手順の切り替わりは
  「変わった」に含めない（例: 実装中にテストを書く、実装中に別ファイルを直す）
- 挨拶や雑談だけで、まだ作業が始まっていないとき
- 単発の質問に答えるだけで、作業として継続しないとき

## 失敗したとき

`herdr-label` は何も出力せず、常に終了コード 0 で終わる。herdr の外で動いている場合、
ソケットが応答しない場合、タブ ID が古い場合も同じ。出力がないのが正常なので、
原因を調べたり再実行したりせず、そのまま本来のタスクを続行する。
タブ名はあくまで補助情報であり、これが原因で本来のタスクを止める価値はない。
