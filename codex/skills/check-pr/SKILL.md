# PR 確認

`gh pr checks` で CI を確認する。失敗したチェックは `gh run list` と `gh run view --log-failed` で原因を調べる。ブランチ上で修正できる問題は修正し、プロジェクトで定められた検証のうち、変更に必要なものを実行する。環境や外部サービスに原因があり修正できない場合は、根拠を示してユーザーへ判断を求める。

GitHub GraphQL API で未解決のレビュースレッドを取得する。各スレッドの全コメントと対象コードを読み、指摘が妥当かをプロジェクトの `AGENTS.md`、spec、実装に照らして判定する。

修正を終えたスレッドや、対応不要と判断したスレッドを解決済みにする前に、GitHub 上の状態を変更することをユーザーに知らせ、必要な承認を得る。対応不要の場合も、その結論と理由を最終報告に必ず含める。理由には `file:line` またはコマンドの出力を根拠として示す。

完了時は CI の状態、各スレッドへの対応、未解決事項を表で報告する。
