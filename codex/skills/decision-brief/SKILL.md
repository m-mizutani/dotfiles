# 判断資料

`AGENTS.md` の User Decisions に従い、ユーザーに判断を求める前に使う。アーキテクチャ、データモデル、外部契約、セキュリティ、永続化に関する選択だけでなく、小さく容易に変更できる選択も対象とする。自分で決める権限がある事項は、ユーザーに選ばせない。資料の長さは判断に必要な内容に合わせる。

関連する実装と公式仕様を確認してから、`.spec/{branch-slug}/decision-{topic}.md` に資料を作る。ブランチ名から slug を取得できない場合は `.spec/decisions/decision-{topic}.md` に作る。資料には次を含める。

- 決める事項と、未決のまま進められない理由
- 冒頭の課題説明。対象の役割、現在の構造と動作、両立できていない要求と制約、単純な方法では解決できない理由、リポジトリ固有の用語の意味を書く。案件の全体や実装の詳細を知らない読者も、この説明だけで課題を理解できるようにする
- 各案を共通の項目で比較する表。通常は3〜5項目とし、小さな判断では結果が異なる項目だけにする
- 各案で変更する箇所、利用者から見た変更前後の動作、後から変更する費用
- 「あるべき姿」と「現実解」の2つの基準で選んだ案。「あるべき姿」は、既存実装に制約されず、長期的な保守性、モデルの整合性、抽象化の適切さを重視して選ぶ。「現実解」は、実装費用、互換性を損なう変更の回避、保守性を考慮して選ぶ。それぞれに採用理由と不利な点を添える。異なる案を選んだ場合は、現実解とあるべき姿の違い、後からあるべき姿へ変更するために必要な作業を書く
- 確認済み・未確認の前提

作成後は `mo <資料のパス>` で表示する。Claude Code の Artifact は使わず、ページ上での選択も待たない。会話でユーザーが答えた内容を決定として扱い、必要があれば資料にも決定内容を追記する。
