# 実装方法の検討

依頼の目的、制約、決める必要がある事項を整理し、最初に関連する実装・テスト・設定を読む。既存のコードを確認せず、推測で案を作らない。

外部仕様や最新の実装例が判断に影響するときは、公式ドキュメントまたは一次情報を確認する。調査範囲が広く、同じ種類の確認を繰り返す場合だけ、独立して調べられる範囲をサブエージェントに委任してよい。

結論を先に示す。選択肢がある場合は、各案の違いが分かる共通の項目で比較し、採用案、却下案、その理由、影響を受けるファイルを示す。設計上重要な選択が未確定なら、実装を始めずにユーザーへ判断を求める。

このスキルでは spec を作成しない。実装方針が決まり、開発へ進む場合は `spec` スキルを使う。
