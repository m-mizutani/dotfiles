# 壁打ち

依頼の目的、制約、決める必要がある点を整理し、最初に関連する実装・テスト・設定を読む。現在のコードに接続しない推測で案を作らない。

外部仕様や最新の実装例が判断を左右するときは、公式 documentation または一次情報を確認する。調査の範囲が広く単調な場合だけ、独立した読み取りを subagent に委譲してよい。

結論を先に示す。選択肢がある場合は、結果が変わる同じ評価軸で比較し、採用案、却下案、理由、影響する実ファイルを示す。設計上重要な選択が未確定なら、実装を始めずにユーザーへ判断を求める。

この skill は spec の代わりではない。実装方針が決まった後に開発へ進む場合は `spec` skill を使う。
