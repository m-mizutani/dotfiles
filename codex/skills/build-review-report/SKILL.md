# 変更レビューレポート

現在のブランチとデフォルトブランチとの差分、および未コミット変更をレビュー対象とする。変更箇所、周辺コード、spec、テストを読み、次の3点を根拠とともに整理する。

1. 利用者から見た変更前後の動作
2. 変更が必要とする検証
3. 検証済みの範囲、検証が不足している範囲、未実施の範囲、検証が不要と判断した範囲

`.spec/{branch-slug}/review-report.md` を作成する。ブランチ名から slug を取得できない場合は `.spec/review-report.md` を使う。冒頭に、変更箇所と検証状況を対応付けた小さな図または表を置く。続けて、変更前後の動作、要件とテストの対応、検証が不足している項目を書く。テスト名を列挙するだけで、必要な検証を実施したと判断しない。

作成後は `mo <レポートのパス>` で表示する。Claude Code の Artifact は使わない。レポートの長い本文を会話に転載しない。
